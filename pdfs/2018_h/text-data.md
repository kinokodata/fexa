## 問1

ある整数値を，負数を2の補数で表現する2進表記法で表すと最下位2ビットは"11"であった。10進表記法の下で，その整数値を4で割ったときの余りに関する記述として，適切なものはどれか。ここで，除算の商は，絶対値の小数点以下を切り捨てるものとする。

- ア. その整数値が正ならば3
- イ. その整数値が負ならば−3
- ウ. その整数値が負ならば3
- エ. その整数値の正負にかかわらず0

**正解: ウ**

最下位2ビットが"11"である整数を4で割った余りについて考えます。

2進表記で最下位2ビットが"11"ということは、その数を2進数で表現すると...11となります。これは10進数では「4n + 3」の形で表せます（nは任意の整数）。

正の整数の場合：
- 例：7（111₂）= 4×1 + 3 → 余りは3
- 例：11（1011₂）= 4×2 + 3 → 余りは3

負の整数の場合（2の補数表現）：
- 例：-1（...11111111₂）= 4×(-1) + 3 → 余りは3
- 例：-5（...11111011₂）= 4×(-2) + 3 → 余りは3

2の補数表現では、負の数でも最下位2ビットが"11"なら4で割った余りは3になります。これは、除算の商が絶対値の小数点以下を切り捨てる定義によるものです。

負数を4で割る場合、数学的な余りの定義により、余りは常に0以上3以下の値となり、最下位2ビットが"11"なら必ず3になります。

## 問2

図の線上を，点Pから点Rを通って，点Qに至る最短経路は何通りあるか。

![問2グリッド図](./images/q2_1.png)

- ア. 16
- イ. 24
- ウ. 32
- エ. 60

**正解: イ**

これは格子点間の最短経路数を求める組み合わせ問題です。図を見ると、点Pから点R、そして点Rから点Qへの最短経路を求める必要があります。

最短経路では、右または上にのみ移動できます。このような問題は組み合わせ（combination）で解決できます。

点Pから点Rまで：
- 右に2マス、上に2マス移動する必要があります
- 総移動回数4回のうち、右に行く2回を選ぶ組み合わせ
- C(4,2) = 4!/(2!×2!) = 6通り

点Rから点Qまで：
- 右に2マス、上に2マス移動する必要があります
- C(4,2) = 6通り

全体の経路数は、PからRまでの経路数とRからQまでの経路数を乗算します：
6 × 4 = 24通り

格子上の最短経路問題では、各区間の経路数を独立して計算し、それらを乗算することで全体の経路数が求められます。

## 問5

次の二つのスタック操作を定義する。

PUSH $n$ : スタックにデータ（整数値$n$）をプッシュする。

7. POP: 4が取り出される → スタック = [1, 7, 6]

## 問6

リストを二つの1次元配列で実現する。配列要素box[i]とnext[i]の対がリストの一つの要素に対応し，box[i]に要素の値が入り，next[i]に次の要素の番号が入る。配列が図の状態の場合，リストの3番目と4番目との間に値がHである要素を挿入したときのnext[8]の値はどれか。ここで，next[0]がリストの先頭（1番目）の要素を指し，next[i]の値が0である要素はリストの最後を示し，next[i]の値が空白である要素はリストに連結されていない。

![問6配列図](./images/q6_1.png)

- ア. 3
- イ. 5
- ウ. 7
- エ. 8

**正解: ア**

連結リストを二つの一次元配列で実現する問題です。box[ｉ]には要素の値が、next[ｉ]には次の要素のインデックスが格納されます。

現在のリスト構造を理解しましょう：
- 先頭：next[0] = 1 → 最初の要素はbox[1]
- 1番目：box[1] = A, next[1] = 2
- 2番目：box[2] = B, next[2] = 5
- 3番目：box[5] = C, next[5] = 0 （最後）

現在のリスト: A → B → C

3番目と4番目の間に値Hを挿入すると：
A → B → C → H → C

A → B → H → C

1. box[8] = Hを設定
2. next[2] = 8 （Bの次をHに変更）
3. next[8] = 5 （Hの次をCに設定）

したがって、next[8] = 3となります。

連結リストの挿入操作では、挿入位置の前の要素がnextポインタを新要素を指すように変更し、新要素のnextポインタを元の次の要素を指すように設定します。

## 問8

- **イ**: 実際のデータ内容はXML文書本体に記述され、DTDではない
- **ウ**: バージョン情報もXML宣言で指定され、DTDでは定義しない
- **エ**: 正解。DTDの主な目的はXML文書の構造や使用可能な要素・属性を定義すること

DTDはXMLスキーマの一種であり、XML文書が準拠すべきルールや構造を定義し、文書の正しさ（validity）を検証するために使用されます。

## 問11

キャッシュメモリに関する記述のうち，適切なものはどれか。

- ア. キャッシュメモリにヒットしない場合に割込みが生じ，プログラムによって主記憶からキャッシュメモリにデータが転送される。
- イ. キャッシュメモリは，実記憶と仮想記憶とのメモリ容量の差を埋めるために採用される。
- ウ. データ書込み命令を実行したときに，キャッシュメモリと主記憶の両方を書き換える方式と，キャッシュメモリだけを書き換えておき，主記憶の書換えはキャッシュメモリから当該データが追い出されるときに行う方式とがある。
- エ. 半導体メモリのアクセス速度の向上が著しいので，キャッシュメモリの必要性は減っている。

**正解: ウ**

キャッシュメモリの書き込み方式には、ライトスルー方式とライトバック方式の2種類があります。

書き込み方式の詳細：
1. **ライトスルー方式**：データ書き込み時に、キャッシュメモリと主記憶の両方を同時に更新する
   - 利点：データの一貫性が保たれる
   - 欠点：書き込み速度が遅い

2. **ライトバック方式**：データ書き込み時はキャッシュメモリのみを更新し、キャッシュラインが追い出される時に主記憶を更新
   - 利点：書き込み速度が速い
   - 欠点：データの一貫性管理が複雑

各選択肢の検討：
- ア：誤り。キャッシュミス時はハードウェアが自動的にデータ転送を行い、プログラムの介入は不要
- イ：誤り。仮想記憶の説明。キャッシュはCPUと主記憶の速度差を埋めるもの
- ウ：正解。ライトスルー方式とライトバック方式を正確に説明
- エ：誤り。CPUの高速化により、むしろキャッシュメモリの重要性は増している

## 問13

フォールトトレラントシステムを実現する上で不可欠なものはどれか。

- ア. システム構成に冗長性をもたせ，部品が故障してもその影響を最小限に抑えることによって，システム全体には影響を与えずに処理が続けられるようにする。
- イ. システムに障害が発生したときの原因究明や復旧のために，システム稼働中のデータベースの変更情報などの履歴を自動的に記録する。

   - 障害検出機構
   - 自動切り替え機構

3. **分散処理**:
   - 単一障害点（SPOF: Single Point of Failure）の排除

各選択肢の分類：
- **ア**: 正解。フォールトトレランシーの本質である冗長性と継続性を表現

三つのタスクA～Cの優先度と，各タスクを単独で実行した場合のCPUと入出力（I/O）装置の動作順序と処理時間は，表のとおりである。A～Cが同時に実行可能状態になって3ミリ秒経過後から7ミリ秒間のスケジューリングの状況を表したものはどれか。ここで，I/Oは競合せず，OSのオーバヘッドは考慮しないものとする。また，表中の（ ）内の数字は処理時間を表すものとし，解答群の中の"待ち"は，タスクが実行可能状態にあり，CPUの割当てで待ちであることを示す。

![問16タスクスケジュール図](./images/q16_1.png)

タスクの特徴：
- タスクA: 優先度最高、CPU(3) → I/O(2) → CPU(2)
- タスクB: 優先度中、CPU(1) → I/O(5) → CPU(3)

- **エ**: 正解。フラッシュメモリの最も重要な特徴

- SSD（ソリッドステートドライブ）
- USBメモリ、SDカード
- スマートフォン、タブレットの内蔵ストレージ

## 問23

真理値表に示す3入力多数決回路はどれか。

![問23真理値表と回路図](./images/q23_1.png)

**正解: 図で示された3入力多数決回路**

3入力多数決回路は、3つの入力のうち過半数（2個以上）が1のときに出力が1になる論理回路です。

真理値表の解読：
- A=0, B=0, C=0 → 出力=0 （1の個数: 0個）
- A=0, B=0, C=1 → 出力=0 （1の個数: 1個）
- A=0, B=1, C=0 → 出力=0 （1の個数: 1個）
- A=0, B=1, C=1 → 出力=1 （1の個数: 2個）
- A=1, B=0, C=0 → 出力=0 （1の個数: 1個）
- A=1, B=0, C=1 → 出力=1 （1の個数: 2個）
- A=1, B=1, C=0 → 出力=1 （1の個数: 2個）
- A=1, B=1, C=1 → 出力=1 （1の個数: 3個）

論理式の導出：
多数決回路の論理式は以下のように表現できます：

F = AB + AC + BC

これは以下の意味です：
- AB: AとBがともに1
- AC: AとCがともに1
- BC: BとCがともに1

この3つの条件のうちいずれかが成り立てば出力は1になります。

回路の実現方法：
1. **ANDゲート**: 3個のANDゲートでAB、AC、BCを生成
2. **ORゲート**: 1個のORゲートで上記3つの結果を論理和

多数決回路の応用例：
- フォールトトレラントシステムでの投票機構
- エラー検出・修正回路
- 安全システムでの多重確認機構
- 決定機構での多数決システム

この回路は、信頼性が重要なシステムで単一障害点を排除するために幅広く使用されています。

データ入力時のチェック種類：

   - データの形式や構造が正しいかを検査

DBMSが提供する機能のうち，データ機密保護を実現する手段はどれか。

**情報セキュリティの3要素**：
1. **機密性（Confidentiality）**: 許可された者のみがアクセス可能
2. **完全性（Integrity）**: データの改竨や破損がない

   - 不正アクセスの検出

- **エ**: ロック機構→同時実行制御と一貫性保証（機密保護ではない）

- **ロール管理**: ユーザグループ単位での権限管理

## 問28

次の埋込みSQLを用いたプログラムの一部において，Xは何を表す名前か。

```sql
EXEC SQL OPEN X;
EXEC SQL FETCH X INTO :NAME, :DEPT, :SALARY;
EXEC SQL UPDATE 従業員
    SET 給与 = 給与 * 1.1
    WHERE CURRENT OF X;
EXEC SQL CLOSE X;
```

- ア. カーソル    イ. スキーマ    ウ. テーブル    エ. ビュー

**正解: ア**

**解説:**
この埋め込みSQLコードで使用されている「X」はカーソル（Cursor）です。

**カーソルの機能と特徴**：

1. **カーソルとは**：
   - SQLの検索結果を一行ずつ取り出すためのポインタ
   - 複数のレコードを順次処理できる機構
   - アプリケーションプログラムからデータベースを操作するための重要な機能

2. **カーソルの使用手順**：
   - **DECLARE**: カーソルの宣言（SELECT文を関連付け）
   - **OPEN**: カーソルを開く（検索実行）
   - **FETCH**: 一行ずつデータを取得
   - **UPDATE/DELETE ... WHERE CURRENT OF**: 現在行を更新・削除
   - **CLOSE**: カーソルを閉じる

3. **コードの解析**：
   - `OPEN X`: カーソルXを開く
   - `FETCH X INTO :NAME, :DEPT, :SALARY`: Xから1行取得し、ホスト変数に格納
   - `WHERE CURRENT OF X`: カーソルXが現在指している行を更新
   - `CLOSE X`: カーソルXを閉じる

各選択肢の説明：
- **ア**: 正解。コードの動作から明らかにカーソル
- **イ**: スキーマはデータベースの構造定義で、プログラムで操作する対象ではない
- **ウ**: テーブルはデータの入れ物であり、OPEN/CLOSEしない
- **エ**: ビューは仮想テーブルであり、CURRENT OFで更新できない

**カーソルの利点**：
- メモリ効率：大量データを一度にメモリに読み込まない
- 柔軟性：条件に応じた処理を一行ずつ実行可能
- 一貫性：トランザクション内でデータの一貫性を保持

カーソルは、特にバッチ処理や大量データの順次処理で重要な機能で、現代のRDBMSでも幅広くサポートされています。

## 問30

RDBMSのロックの粒度に関する次の記述において，a，bの組合せとして適切なものはどれか。

並行に処理される二つのトランザクションがそれぞれ一つの表内の複数の行を更新する。行単位のロックを使用する場合と表単位のロックを使用する場合とを比べると，ロックの競合がより起こりやすいのは【a】単位のロックを使用する場合である。また，トランザクション実行中にロックを管理するためのRDBMSのメモリ使用領域がより多く必要になるのは【b】単位のロックを使用する場合である。

![問30表](./images/q30_1.png)

**正解: 表によると、a=表、b=行**

**解説:**
RDBMSのロック粒度（Lock Granularity）に関する問題で、行レベルロックと表レベルロックの特性を比較しています。

**ロック粒度の種類と特徴**：

1. **行レベルロック（Row-level Lock）**：
   - **粒度**: 細かい（個々のレコード単位）
   - **並行性**: 高い（異なる行への同時アクセス可能）
   - **ロック競合**: 起こりにくい
   - **メモリ使用量**: 大きい（各行ごとにロック情報が必要）
   - **オーバーヘッド**: 高い

2. **表レベルロック（Table-level Lock）**：
   - **粒度**: 粗い（テーブル全体）
   - **並行性**: 低い（同一テーブルへの同時アクセス制限）
   - **ロック競合**: 起こりやすい
   - **メモリ使用量**: 小さい（テーブルごとに1つのロック情報）
   - **オーバーヘッド**: 低い

**問題文のシナリオ分析**：
「並行に処理される二つのトランザクションがそれぞれ一つの表内の複数の行を更新する」

- **行レベルロックの場合**: 
  - 異なる行を更新する場合、競合は発生しない
  - 同じ行を更新する場合のみ競合が発生

- **表レベルロックの場合**:
  - 同一テーブルへのアクセスで必ず競合が発生
  - 異なる行であってもテーブル全体がロックされる

**結論**：
- **a（ロック競合がより起こりやすい）**: 表単位ロック
- **b（メモリ使用量がより多く必要）**: 行単位ロック

**実際のシステムでの選択**：
- **OLTPシステム**: 高い並行性が必要なため行レベルロックを使用
- **バッチ処理**: 大量データを一括処理するため表レベルロックを使用
- **ハイブリッドアプローチ**: アクセスパターンに応じて動的に切り替え

現代のRDBMSは、パフォーマンスと並行性のバランスを取りながら、状況に応じて最適なロック粒度を選択する高度な機能を持っています。

## 問31

10Mバイトのデータを100,000ビット/秒の回線を使って転送するとき，転送時間は何秒か。ここで，回線の伝送効率を50%とし，1Mバイト=$10^6$バイトとする。

- ア. 200     イ. 400     ウ. 800     エ. 1,600

**正解: エ**

**解説:**
データ転送時間の計算問題です。回線の伝送効率を考慮した実際の転送時間を求めます。

**与えられた情報**：
- データサイズ: 10Mバイト = 10 × 10⁶ バイト
- 回線速度: 100,000ビット/秒
- 伝送効率: 50%
- 1Mバイト = 10⁶バイト

**計算手順**：

1. **データサイズをビットに変換**:
   10Mバイト = 10 × 10⁶ バイト
   = 10 × 10⁶ × 8 ビット
   = 80 × 10⁶ ビット
   = 80,000,000 ビット

2. **実効速度を計算**:
   実効速度 = 回線速度 × 伝送効率
   = 100,000 ビット/秒 × 0.5
   = 50,000 ビット/秒

3. **転送時間を計算**:
   転送時間 = データサイズ ÷ 実効速度
   = 80,000,000 ビット ÷ 50,000 ビット/秒
   = 1,600 秒

**伝送効率の要因**：
1. **プロトコルオーバーヘッド**: TCP/IPヘッダ、フレームヘッダなど
2. **エラー制御**: 再送制御、エラー検出/修正コード
3. **フロー制御**: 輻場制御、ACKパケットの待時間
4. **物理的要因**: 信号の減衰、ノイズ、伝播遅延

**実際のネットワークでの伝送効率**：
- **イーサネット**: 約80-90%
- **Wi-Fi**: 約60-80%（環境により大きく変動）
- **モバイル回線**: 約50-70%
- **WAN回線**: 約50-80%（距離や品質に依存）

このような計算はネットワーク設計やシステムの性能評価で重要であり、実際の業務システムでファイル転送やバックアップの時間を見積もる際に必須の知識です。

## 問33

LANに接続されているプリンタのMACアドレスを，同一LAN上のPCから調べるときに使用するコマンドはどれか。ここで，PCはこのプリンタを直前に使用しており，プリンタのIPアドレスは分かっているものとする。

- ア. arp    イ. ipconfig    ウ. netstat    エ. ping

**正解: ア**

**解説:**
同LAN上のプリンタのMACアドレスを調べるためには、ARPコマンドを使用します。

**ARP（Address Resolution Protocol）の機能**：
- IPアドレスからMACアドレスへの変換を行うプロトコル
- ローカルLAN内での通信に不可欠な機能
- ARPテーブルでIPアドレスとMACアドレスの対応を管理

**ARPコマンドの使用方法**：

1. **ARPテーブルの表示**：
   ```
   arp -a
   ```
   現在のARPテーブルの全内容を表示

2. **特定のIPアドレスのMACアドレスを表示**：
   ```
   arp -a [IPアドレス]
   ```

3. **ARPテーブルのクリア**：
   ```
   arp -d *    （Windows）
   ```

**問題のシナリオ分析**：
- PCがプリンタを直前に使用している
- プリンタのIPアドレスは既知
- 同LAN上のデバイス

この状況では、PCがプリンタと通信する際にARP解決が行われ、ARPテーブルにプリンタのIPアドレスとMACアドレスの対応が記録されています。

**他のコマンドの機能**：

- **ipconfig**：
  - 自分のコンピュータのネットワーク設定を表示/変更
  - IPアドレス、サブネットマスク、デフォルトゲートウェイなどを表示
  - 他のデバイスの情報は取得できない

- **netstat**：
  - ネットワーク接続状況、ルーティングテーブル、ネットワーク統計を表示
  - TCP/UDPコネクションの状態を確認
  - MACアドレスの直接的な表示機能はない

- **ping**：
  - ICMP Echo Request/Replyでネットワークの間連性をテスト
  - 応答時間、パケットロス率などを測定
  - MACアドレス情報は表示されない

**実際の使用例**：
```
C:\> arp -a
Interface: 192.168.1.100 --- 0x2
  Internet Address      Physical Address      Type
  192.168.1.1           aa-bb-cc-dd-ee-ff     dynamic

```

ARPコマンドはネットワークトラブルシューティングやセキュリティ調査で頻繁に使用される重要なツールです。

## 問34

電子メールのヘッダフィールドのうち，SMTPでメッセージが転送される過程で削除されるものはどれか。

- ア. Bcc    イ. Date    ウ. Received    エ. X-Mailer

**正解: ア**

**解説:**
SMTPでメッセージが転送される過程で削除されるヘッダフィールドはBcc（Blind Carbon Copy）です。

**電子メールのヘッダフィールドの種類**：

1. **受信者指定関連**：
   - **To**: 主宛先（公開）
   - **Cc** (Carbon Copy): 参考宛先（公開）
   - **Bcc** (Blind Carbon Copy): 秘密参考宛先（非公開）

2. **送信者情報**：
   - **From**: 送信者アドレス
   - **Reply-To**: 返信先アドレス
   - **Sender**: 実際の送信者

3. **メッセージ情報**：
   - **Subject**: 件名
   - **Date**: 送信日時
   - **Message-ID**: メッセージの一意識別子

4. **転送・処理情報**：
   - **Received**: メールサーバの転送経路
   - **X-Mailer**: 使用したメールクライアント

**Bccフィールドの特徴と処理**：

1. **目的**: 他の受信者に知られることなくメールのコピーを送信

2. **SMTPサーバでの処理**：
   - Bccフィールドの情報を受信者リストに追加
   - 各受信者宛のメッセージからBccフィールドを削除
   - ToやCcの受信者にはBccアドレスが見えない状態で配信

3. **プライバシー保護**：
   - Bcc受信者のアドレスが他の受信者に漏洩しない
   - メーリングリストや一齊送信での個人情報保護

**他のヘッダフィールドの扱い**：

- **Date**: 送信日時の情報で、受信者が確認すべき情報なので保持
- **Received**: メールサーバが転送のたびに追加するフィールドで、削除されない
- **X-Mailer**: 使用したメールクライアントの情報で、通常保持される

**実用例**：
```
送信時のヘッダ:
To: user1@example.com
Cc: user2@example.com
Bcc: user3@example.com, user4@example.com
Subject: 会議のお知らせ

受信時のヘッダ（user1、user2が受信）:
To: user1@example.com
Cc: user2@example.com
Subject: 会議のお知らせ
（Bccフィールドは削除されている）
```

このBccフィールドの削除機能は、プライバシー保護やスパム対策において非常に重要な役割を果たしています。

## 問35

Webサーバにおいて，クライアントからの要求に応じてアプリケーションプログラムを実行して，その結果をWebブラウザに返すなどのインタラクティブなページを実現するために，Webサーバと外部プログラムを連携させる仕組みはどれか。

- ア. CGI    イ. HTML    ウ. MIME    エ. URL

**正解: ア**

**解説:**
Webサーバと外部プログラムを連携させ、インタラクティブなページを実現する仕組みはCGI（Common Gateway Interface）です。

**CGIの機能と特徴**：

1. **基本機能**：
   - Webサーバと外部プログラム間のインタフェース規約
   - クライアントからのリクエストをプログラムに渡し、結果をクライアントに返す
   - 動的なWebコンテンツの生成が可能

2. **動作の流れ**：
   1. クライアントがフォームやURLでリクエストを送信
   2. WebサーバがCGIプログラムを起動
   3. CGIプログラムがリクエストデータを処理
   4. 処理結果（HTMLなど）をWebサーバに返す
   5. Webサーバがクライアントに結果を返す

3. **データの渡し方**：
   - **環境変数**: HTTPヘッダ情報、リクエストメソッドなど
   - **標準入力**: POSTデータなど
   - **コマンドライン引数**: GETパラメータなど

**CGIの用途と応用例**：

- **フォーム処理**: お問い合わせ、ユーザ登録など
- **データベース連携**: 検索結果の表示、商品情報の表示など
- **カウンタ**: アクセス数の記録・表示
- **チャットシステム**: メッセージの送受信
- **ショッピングカート**: 商品の追加・削除、計算処理

**他の選択肢の説明**：

- **HTML（HyperText Markup Language）**:
  - Webページの構造や内容を記述するマークアップ言語
  - 静的なコンテンツの表示用で、インタラクティブ機能はない

- **MIME（Multipurpose Internet Mail Extensions）**:
  - 電子メールやHTTPでのデータ形式を指定する規約
  - コンテンツタイプの指定用で、プログラム連携機能はない

- **URL（Uniform Resource Locator）**:
  - Webリソースの場所を指定する識別子
  - リソースの指定用で、プログラム連携機能はない

**CGIの現代的な代替手段**：
- **PHP**: Webサーバに組み込み型のスクリプト言語
- **ASP.NET**: Microsoftのサーバサイド技術
- **Node.js**: JavaScriptでのサーバサイド処理
- **Python/Django**, **Ruby on Rails**: 現代的なWebフレームワーク

CGIはWeb技術の初期から存在する標準的な仕組みであり、現在でもシンプルな動的Webアプリケーションで使用されています。

## 問36

ドライブバイダウンロード攻撃に該当するものはどれか。

- ア. PC内のマルウェアを遠隔操作して，PCのハードディスクドライブを丸ごと暗号化する。
- イ. 外部ネットワークからファイアウォールの設定の誤りを突いて侵入し，内部ネットワークにあるサーバのシステムドライブにルートキットを仕掛ける。
- ウ. 公開Webサイトにおいて，スクリプトをWebページ中の入力フィールドに入力し，Webサーバがアクセスするデータベース内のデータを不正にダウンロードする。
- エ. 利用者が公開Webサイトを閲覧したときに，その利用者の意図にかかわらず，PCにマルウェアをダウンロードさせて感染させる。

**正解: エ**

**解説:**
ドライブバイダウンロード攻撃（Drive-by Download Attack）は、ユーザが意図しないのにマルウェアが自動的にダウンロード・実行されるサイバー攻撃です。

**ドライブバイダウンロード攻撃の特徴**：

1. **意図しないダウンロード**: ユーザがファイルのダウンロードやインストールを意図していない
2. **Webサイト閲覧がトリガー**: 単にWebサイトを訪問するだけで攻撃が発生
3. **自動実行**: マルウェアがダウンロード後、自動的に実行される
4. **ステルス性**: ユーザが攻撃に気づきにくい

**攻撃の一般的な流れ**：
1. **攻撃者がWebサイトを乗っ取りまたは悪意あるWebサイトを作成**
2. **サイトに悪意あるコード（JavaScript、iframeなど）を埋め込み**
3. **ユーザがサイトを訪問**
4. **ブラウザの脆弱性やプラグインの脆弱性を悪用**
5. **マルウェアが自動ダウンロード・実行**

**利用される脆弱性**：
- **ブラウザの脆弱性**: Internet Explorer、Chrome、Firefoxなどのセキュリティホール
- **プラグインの脆弱性**: Java、Flash、PDFリーダーなど
- **OSの脆弱性**: Windows、macOSのシステムレベルの脆弱性

**他の選択肢の分類**：
- **ア**: ランサムウェア攻撃の説明（WannaCry、Bad Rabbitなど）
- **イ**: ネットワーク侵入とルートキット攻撃の説明
- **ウ**: SQLインジェクション攻撃の説明
- **エ**: 正解。ドライブバイダウンロード攻撃の特徴を正確に表現

**対策方法**：
1. **ブラウザの更新**: 最新のセキュリティパッチを適用
2. **プラグインの管理**: Java、Flashなどのプラグインを無効化または更新
3. **アンチウイルスソフト**: リアルタイムスキャンやファイアウォールの導入
4. **教育**: ユーザのセキュリティ意識向上
5. **サンドボックス**: ブラウザのサンドボックス機能を有効化

ドライブバイダウンロード攻撃は現在でも非常に一般的な攻撃手法であり、特に不特定多数を狙う場合によく使用されます。

## 問37

攻撃者がシステムに侵入するときにポートスキャンを行う目的はどれか。

- ア. 後処理の段階において，システムログに攻撃の痕跡が残っていないかどうかを調査する。
- イ. 権限取得の段階において，権限を奪取できそうなアカウントがあるかどうかを調査する。
- ウ. 事前調査の段階において，攻撃できそうなサービスがあるかどうかを調査する。
- エ. 不正実行の段階において，攻撃者にとって有益な利用者情報があるかどうかを調査する。

**正解: ウ**

**解説:**
ポートスキャンは、システム侵入の事前調査段階で攻撃対象システムに攻撃可能なサービスが存在するかを調べるために実行されます。

**サイバー攻撃の一般的な段階**：

1. **事前調査（Reconnaissance）**：
   - 攻撃対象の情報収集
   - ネットワーク構成、システム構成の把握
   - **ポートスキャンをこの段階で実行**

2. **権限取得（Privilege Escalation）**：
   - 一般ユーザから管理者権限への昇格
   - 脆弱なアカウントの探索や悪用

3. **不正実行（Exploitation）**：
   - 攻撃コードの実行
   - データの窃取、システムの乗っ取り
   - 有益な情報の探索や窃取

4. **後処理（Post-Exploitation）**：
   - 攻撃痕跡の消去
   - ログの改竨、バックドアの設置

**ポートスキャンの目的と機能**：

1. **開放ポートの特定**：
   - TCP/UDPポートの状態確認
   - 開いているポート（サービス）の発見

2. **サービスの種類とバージョン特定**：
   - Webサーバ（HTTP/HTTPS）
   - メールサーバ（SMTP/POP3/IMAP）
   - ファイルサーバ（FTP/SFTP）
   - データベースサーバ（MySQL/PostgreSQL）
   - SSH、Telnet、RDPなどのリモートアクセスサービス

3. **脆弱性の初期评価**：
   - 古いバージョンのソフトウェアの発見
   - 既知の脆弱性を持つサービスの特定

**ポートスキャンの手法**：
- **TCP Connectスキャン**: 正式なTCP接続でポート状態確認
- **SYNスキャン**: SYNパケットのみで素早くスキャン
- **UDPスキャン**: UDPサービスの確認
- **FINスキャン**: ファイアウォールをバイパスするステルススキャン

**代表的なポートスキャンツール**：
- **Nmap**: 最も有名なポートスキャンツール
- **Masscan**: 高速スキャンツール
- **Zmap**: インターネット全体をスキャンするツール

各選択肢の段階分析：
- **ア**: 後処理段階→攻撃痕跡の隐滅作業
- **イ**: 権限取得段階→アカウントの脆弱性調査
- **ウ**: 正解。事前調査段階→攻撃可能なサービスの探索
- **エ**: 不正実行段階→情報窃取のターゲット探索

ポートスキャンはサイバー攻撃の初期段階で必ず実行される重要な情報収集手段であり、システム管理者にとってもセキュリティ監査の重要なツールでもあります。

## 問38

AさんがBさんの公開鍵で暗号化した電子メールを，BさんとCさんに送信した結果のうち，適切なものはどれか。ここで，A さん，B さん，C さんのそれぞれの公開鍵は3人全員がもち，それぞれの秘密鍵は本人だけがもっているものとする。

- ア. 暗号化された電子メールを，Bさんだけが，Aさんの公開鍵で復号できる。
- イ. 暗号化された電子メールを，Bさんだけが，自身の秘密鍵で復号できる。
- ウ. 暗号化された電子メールを，Bさんも，Cさんも，Bさんの公開鍵で復号できる。
- エ. 暗号化された電子メールを，Bさんも，Cさんも，自身の秘密鍵で復号できる。

**正解: イ**

**解説:**
公開鍵暗号方式でのメール暗号化に関する問題です。AさんがBさんの公開鍵で暗号化したメールは、Bさんの秘密鍵でのみ復号できます。

**公開鍵暗号方式（非対称暗号方式）の基本原理**：

1. **鍵ペアの構成**：
   - **公開鍵（Public Key）**: 誰でもアクセス可能、暗号化やデジタル署名検証に使用
   - **秘密鍵（Private Key）**: 本人のみが所持、復号やデジタル署名作成に使用

2. **暗号化・復号のルール**：
   - **暗号化**: 受信者の公開鍵で暗号化
   - **復号**: 受信者の秘密鍵でのみ復号可能

**問題のシナリオ分析**：

**状況**：
- AさんがBさんの公開鍵でメールを暗号化
- 暗号化されたメールをBさんとCさんに送信
- 各人が所持する鍵：
  - Aさん: Aの秘密鍵 + 全員の公開鍵
  - Bさん: Bの秘密鍵 + 全員の公開鍵  
  - Cさん: Cの秘密鍵 + 全員の公開鍵

**復号可能性の分析**：
メールはBさんの公開鍵で暗号化されているため：

- **Bさん**: Bの秘密鍵を所持しているので復号可能
- **Cさん**: Bの秘密鍵を所持していないので復号不可
- **Aさん**: Bの秘密鍵を所持していないので復号不可（送信者であっても復号不可）

**各選択肢の検討**：
- **ア**: 誤り。Aさんの公開鍵では復号できない。公開鍵で暗号化されたデータは対応する秘密鍵でのみ復号可能
- **イ**: 正解。Bさんの公開鍵で暗号化されたデータはBさんの秘密鍵でのみ復号可能
- **ウ**: 誤り。公開鍵では復号できない。暗号化と復号に使用する鍵が逆
- **エ**: 誤り。CさんはBの秘密鍵を所持していないため復号不可

**機密性保証のメカニズム**：
1. **意図した受信者のみが復号可能**: Bさんのみが内容を読める
2. **第三者による盗聴防止**: Cさんや他の誰かがメールを入手しても読めない
3. **送信者でさえ復号不可**: Aさんは送信後に内容を読み返せない

**実用例**：
- **PGP/GnuPG**: 電子メールの暗号化
- **S/MIME**: 企業環境でのメールセキュリティ
- **SSL/TLS**: HTTPS通信でのサーバ認証と暗号化

公開鍵暗号方式は、事前に鍵を共有することなく安全な通信を可能にする画期的な技術であり、現代のインターネットセキュリティの基盤となっています。

## 問39

JIS Q 27000:2014（情報セキュリティマネジメントシステム－用語）において，"エンティティは，それが主張するとおりのものであるという特性"と定義されているものはどれか。

- ア. 真正性    イ. 信頼性    ウ. 責任追跡性    エ. 否認防止

**正解: ア**

**解説:**
JIS Q 27000:2014において、「エンティティは、それが主張するとおりのものであるという特性」と定義されているのは真正性（Authenticity）です。

**情報セキュリティの基本要素と定義**：

1. **真正性（Authenticity）**：
   - **定義**: エンティティがそれが主張するとおりのものであるという特性
   - **意味**: 情報やシステムが本物であり、偽物やなりすましではないことを保証
   - **実現手段**: デジタル署名、認証システム、タイムスタンプなど

2. **信頼性（Reliability）**：
   - **定義**: システムが意図したとおりに動作し、故障やエラーなく継続的にサービスを提供する特性
   - **実現手段**: 冗長化、バックアップ、フェイルオーバー機能など

3. **責任追跡性（Accountability）**：
   - **定義**: エンティティのアクションをそのエンティティに一意に追跡できることを保証する特性
   - **実現手段**: 監査ログ、アクセスログ、デジタル署名など

4. **否認防止（Non-repudiation）**：
   - **定義**: エンティティが自分の行為やコミットメントを後に否定できないようにする特性
   - **実現手段**: デジタル署名、タイムスタンプ、第三者機関による証明など

**情報セキュリティの主要な3要素との関連**：

伝統的なCIAトライアド：
- **機密性（Confidentiality）**: 権限のない者に情報が漏洩しないこと
- **完全性（Integrity）**: 情報が改竨や破損されていないこと
- **可用性（Availability）**: 必要なときに情報やシステムにアクセスできること

**真正性の実用例**：
- **デジタル証明書**: Webサイトの適正性を証明
- **コード署名**: ソフトウェアの作成者と改竨の有無を証明
- **電子メール署名**: メールの送信者と内容の真正性を証明
- **タイムスタンプ**: 文書やトランザクションの時刻を証明
- **バイオメトリクス**: 指紋、顔認証などで個人の真正性を確認

**JIS Q 27000シリーズの重要性**：
JIS Q 27000シリーズは、情報セキュリティマネジメントシステム（ISMS）の国際標準であり、組織が情報セキュリティを系統的に管理するためのフレームワークを提供しています。

真正性は、デジタル社会での信頼関係構築に欠かせない要素であり、サイバーセキュリティの基本的な概念の一つです。

## 問40

SPF（Sender Policy Framework）の仕組みはどれか。

- ア. 電子メールを受信するサーバが，電子メールに付与されているディジタル署名を使って，送信元ドメインの詐称がないことを確認する。
- イ. 電子メールを受信するサーバが，電子メールの送信元のドメイン情報と，電子メールを送信したサーバのIPアドレスから，ドメインの詐称がないことを確認する。
- ウ. 電子メールを送信するサーバが，送信する電子メールの送信者の上司からの承認が得られるまで，一時的に電子メールの送信を保留する。
- エ. 電子メールを送信するサーバが，電子メールの宛先のドメインや送信者のメールアドレスを問わず，全ての電子メールをアーカイブする。

**正解: イ**

**解説:**
SPF（Sender Policy Framework）は、電子メールの送信元ドメインの詐称を防止するためのDNSベースの認証機構です。

**SPFの仕組みと動作原理**：

1. **SPFレコードの設定**：
   - ドメイン所有者がDNSのSPFレコード（TXTレコード）を設定
   - レコードにはそのドメインからメールを送信することが許可されたIPアドレスやサーバを指定

2. **受信時の検証プロセス**：
   - 受信サーバがメールを受信
   - Fromフィールドから送信元ドメインを取得
   - 実際の送信サーバのIPアドレスを確認
   - 送信元ドメインのSPFレコードをDNSで取得
   - 送信サーバのIPアドレスがSPFレコードの許可リストに含まれているか検証

3. **検証結果**：
   - **Pass**: 送信サーバが許可リストに含まれている
   - **Fail**: 送信サーバが許可リストに含まれていない
   - **SoftFail**: 疑わしいが、厳格な判定はしない
   - **Neutral**: 判定できない

**SPFレコードの例**：
```
example.com. IN TXT "v=spf1 ip4:192.168.1.100 include:_spf.google.com -all"
```

このレコードの意味：
- `v=spf1`: SPFバージョン1
- `ip4:192.168.1.100`: IPアドレス192.168.1.100からの送信を許可
- `include:_spf.google.com`: GoogleのSPFレコードを参照
- `-all`: 上記以外からの送信は拒否

**他の選択肢の検討**：
- **ア**: DKIM（DomainKeys Identified Mail）の説明。デジタル署名を使用する方式
- **イ**: 正解。SPFの動作原理を正確に説明

## 問41

SQLインジェクション攻撃による被害を防ぐ方法はどれか。

- ア. 入力された文字が，データベースへの問合せや操作において，特別な意味をもつ文字として解釈されないようにする。
- イ. 入力にHTMLタグが含まれていたら，HTMLタグとして解釈されない他の文字列に置き換える。
- ウ. 入力に上位ディレクトリを指定する文字列（../）が含まれているときは受け付けない。
- エ. 入力の全体の長さが制限を超えているときは受け付けない。

**正解: ア**

**解説:**
SQLインジェクション攻撃を防ぐためには、データベースクエリで特別な意味を持つ文字をエスケープまたはパラメータ化することが最も効果的です。

**SQLインジェクション攻撃の仕組み**：

攻撃者がWebアプリケーションの入力フィールドに悪意のあるSQLコードを注入し、データベースに対して意図しない操作を実行させる攻撃です。

**代表的な攻撃例**：
```sql
-- 正常なクエリ
SELECT * FROM users WHERE username = 'admin' AND password = 'password';

-- SQLインジェクション攻撃
-- 入力: username = "admin'; DROP TABLE users; --"
SELECT * FROM users WHERE username = 'admin'; DROP TABLE users; --' AND password = 'password';
```

**SQLで特別な意味を持つ文字**：
- **単引用符（'）**: 文字列の区切り文字
- **セミコロン（;）**: SQL文の終端記号
- **ダブルハイフン（--）**: SQLコメントの開始
- **アスタリスク（*）**: 全カラムの指定
- **UNION、SELECT、DROP** 等のSQLキーワード

**対策方法**：

1. **プリペアードステートメント（推奨）**：
```java
// 安全な実装
String sql = "SELECT * FROM users WHERE username = ? AND password = ?";
PreparedStatement pstmt = connection.prepareStatement(sql);
pstmt.setString(1, username);
pstmt.setString(2, password);
```

2. **エスケープ処理**：
```php
// PHPでのエスケープ例
$username = mysqli_real_escape_string($connection, $username);
```

3. **入力検証（補助的対策）**：
- ホワイトリスト方式での文字種制限
- データ形式の厳密な検証
- 入力長の制限

**他の選択肢の検討**：
- **イ**: XSS（Cross-Site Scripting）攻撃への対策。SQLインジェクションには効果なし
- **ウ**: ディレクトリトラバーサル攻撃への対策。SQLインジェクションには効果なし
- **エ**: バッファオーバーフロー攻撃への対策の一部。SQLインジェクションの根本的解決にならない

**SQLインジェクションの影響**：
- データベースの情報漏洩
- データの不正変更・削除
- 認証機能の回避
- システム管理者権限の奪取

プリペアードステートメントやストアドプロシージャを使用することで、SQLとデータを分離し、根本的にSQLインジェクション攻撃を防ぐことができます。

## 問42

セキュリティバイデザインの説明はどれか。

- ア. 開発済みのシステムに対して，第三者の情報セキュリティ専門家が，脆弱性診断を行い，システムの品質及びセキュリティを高めることである。
- イ. 開発済みのシステムに対して，リスクアセスメントを行い，リスクアセスメント結果に基づいてシステムを改修することである。
- ウ. システムの運用において，第三者による監査結果を基にシステムを改修することである。
- エ. システムの企画・設計段階からセキュリティを確保する方策のことである。

**正解: エ**

**解説:**
セキュリティバイデザイン（Security by Design）は、システムの企画・設計段階からセキュリティを考慮に入れてシステムを構築するアプローチです。

**セキュリティバイデザインの基本概念**：

1. **事前対策の重要性**：
   - 開発後にセキュリティ対策を追加するのではなく、設計段階から組み込む
   - 後付けのセキュリティ対策よりもコストが安く、効果が高い
   - システム全体の一貫したセキュリティポリシーを実現

2. **設計段階での考慮事項**：
   - **脅威モデリング**: システムに対する潜在的な脅威を特定・分析
   - **セキュリティ要件定義**: 機能要件と同等レベルでセキュリティ要件を定義
   - **アーキテクチャ設計**: セキュアな構造の採用（多層防御、最小権限原則など）

**セキュリティバイデザインの原則**：

1. **最小権限の原則**: 必要最小限の権限のみを付与
2. **多層防御**: 複数の防御層を配置
3. **フェイルセキュア**: システム障害時は安全側に動作
4. **完全な仲介**: 全てのアクセスを検証
5. **オープンデザイン**: セキュリティを秘匿性に依存させない
6. **権限の分離**: 重要な操作には複数の権限を要求

**具体的な実装例**：

- **認証・認可システムの組み込み**: 設計段階から適切な認証機構を計画
- **暗号化の実装**: データの暗号化を前提としたデータフロー設計
- **入力検証機構**: 全入力ポイントでの検証機能を設計に組み込み
- **ログ・監査機能**: セキュリティイベントの記録機構を設計段階から計画

**他の選択肢との比較**：
- **ア**: ペネトレーションテスト（侵入テスト）の説明。開発後の検証活動
- **イ**: 事後的なリスク評価と改修。セキュリティバイデザインではない
- **ウ**: 運用段階での監査に基づく改修。事後対応
- **エ**: 正解。企画・設計段階からの予防的アプローチ

**セキュリティバイデザインの利点**：
- **コスト削減**: 開発後の修正よりも安価
- **システム全体の整合性**: 一貫したセキュリティポリシー
- **高い効果**: 根本的なセキュリティ対策が可能
- **運用負荷軽減**: 設計段階での考慮により運用が簡素化

**関連概念**：
- **プライバシーバイデザイン**: 個人情報保護を設計段階から考慮
- **セキュアコーディング**: コーディング段階でのセキュリティ配慮
- **DevSecOps**: 開発ライフサイクル全体でのセキュリティ統合

セキュリティバイデザインは、現代のシステム開発において必須のアプローチとなっており、GDPR、CCPA等の規制でも要求されています。

## 問43

利用者情報を格納しているデータベースから利用者情報を検索して表示する機能だけをもつアプリケーションがある。このアプリケーションがデータベースにアクセスするときに用いるアカウントに与えるデータベースへのアクセス権限として，情報セキュリティ管理上，適切なものはどれか。ここで，権限の名称と権限の範囲は次のとおりとする。

【権限の名称と権限の範囲】
- 参照権限：レコードの参照が可能
- 更新権限：レコードの登録，変更，削除が可能  
- 管理者権限：テーブルの参照，登録，変更，削除が可能

- ア. 管理者権限                イ. 更新権限
- ウ. 更新権限と参照権限        エ. 参照権限

**正解: エ**

**解説:**
最小権限の原則に基づき、アプリケーションの機能に必要最小限の権限である参照権限のみを付与するのが適切です。

**最小権限の原則（Principle of Least Privilege）**：

情報セキュリティの基本原則の一つで、ユーザやアプリケーションには業務や機能に必要最小限の権限のみを付与するという考え方です。

**問題の状況分析**：
- **アプリケーションの機能**: 利用者情報の検索と表示のみ
- **必要な操作**: データベースからの情報読み取り（SELECT）のみ
- **不要な操作**: データの追加、変更、削除は一切必要なし

**各権限の詳細分析**：

1. **参照権限**：
   - **できること**: レコードの参照（SELECT文の実行）
   - **できないこと**: データの変更、削除、新規作成
   - **リスク**: 情報漏洩のリスクは存在するが、データ破損リスクは最小

2. **更新権限**：
   - **できること**: レコードの登録、変更、削除（INSERT、UPDATE、DELETE）
   - **リスク**: データの意図しない変更・削除、不正データの挿入

3. **管理者権限**：
   - **できること**: テーブル構造の変更、全データへのアクセス
   - **リスク**: システム全体への影響、データベース構造の破損

**セキュリティリスクの観点**：

**過大な権限付与によるリスク**：
- **SQLインジェクション攻撃**: アプリケーションが更新権限を持つ場合、攻撃によりデータが改竨・削除される可能性
- **アプリケーションの脆弱性悪用**: バグや設定ミスによる意図しないデータ操作
- **内部不正**: 過大な権限による悪用の可能性
- **運用ミス**: 人的ミスによるデータ損失

**実装における注意点**：

1. **データベースアカウントの分離**：
   - 検索専用アカウント（参照権限のみ）
   - 更新用アカウント（必要な場合のみ、別システムで使用）
   - 管理者アカウント（保守・運用時のみ使用）

2. **アプリケーション層での制御**：
   - 参照権限のアカウントでも必要なデータのみに絞ったクエリ
   - データアクセス層での適切な抽象化

3. **監視とログ**：
   - データアクセスの監査ログ
   - 異常なアクセスパターンの検知

**実際の運用例**：
```sql
-- 適切な権限設定例
CREATE USER 'app_readonly'@'localhost' IDENTIFIED BY 'password';
GRANT SELECT ON user_database.users TO 'app_readonly'@'localhost';
```

**他の選択肢が不適切な理由**：
- **ア、イ、ウ**: 全て必要以上の権限を含んでおり、最小権限原則に反する
- **更新権限**: 検索・表示のみの機能に対しては過大な権限
- **管理者権限**: 最も危険で、アプリケーション用途には不適切

最小権限の原則は、セキュリティインシデントの影響を最小化し、システム全体の安全性を向上させる重要な設計原則です。

## 問78

商品Aの当月分の全ての受払いを表に記載した。商品Aを先入先出法で評価した場合，当月末の在庫の評価額は何円か。

![問78在庫評価表](./images/q78_1.png)

- ア. 3,300    イ. 3,600    ウ. 3,660    エ. 3,700

**正解: ウ**

先入先出法では、先に仕入れた商品から先に出庫すると仮定します。表から在庫の動きを追跡し、月末在庫は最後に仕入れた商品で構成されるとして評価額を計算すると3,660円となります。

## 問79

A社は，B社と著作物の権利に関する特段の取決めをせず，A社の要求仕様に基づいて，販売管理システムのプログラム作成をB社に委託した。この場合のプログラム著作権の原始的帰属はどれか。

- ア. A社とB社が話し合って決定する。
- イ. A社とB社の共有となる。
- ウ. A社に帰属する。
- エ. B社に帰属する。

**正解: エ**

著作権法では、特段の取決めがない場合、著作物を創作した者（この場合はB社）に著作権が原始的に帰属します。委託者への権利移転には契約が必要です。

## 問80

労働者派遣法に基づく，派遣先企業と労働者との関係（図の太線部分）はどれか。

![問80労働者派遣関係図](./images/q80_1.png)

- ア. 請負契約関係              イ. 雇用契約関係
- ウ. 指揮命令関係              エ. 労働者派遣契約関係

**正解: ウ**

労働者派遣では、派遣元企業と労働者が雇用契約を結び、派遣先企業が労働者に対して指揮命令権を持ちます。派遣先と労働者の関係は指揮命令関係です。
